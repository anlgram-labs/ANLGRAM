# F-02 principal ledger experiment — uncompiled and untested

This branch contains a **non-integrated arithmetic experiment**, not a working escrow, migration engine, recovery system, or deployment candidate. The library has no account or transfer entrypoint. The only message handler is in a test-only harness and always throws 414; this does not guarantee return of non-bounceable funds. No existing contract imports the experiment; production Gate 414 and economics are unchanged. Do not deploy or fund the harness.

For a single operation and asset, the proposed calculation validates nonnegative integers and bounds `dispatched <= received`, `returned <= dispatched`, and `paid + pending <= received - dispatched + returned`. It returns an arithmetic remainder and `dispatched - returned` as unresolved external exposure. A zero output does not prove that the DEX has no delayed messages. Values are inputs, not evidence: the function does not authenticate a wallet, validate a transfer, enforce unique sessions, protect custody or make payouts. In particular, a sent message cannot be counted as a delivered payout. Fees and native gas are outside this principal calculation.

The test harness and its Sandbox test are written but **have not been compiled or run**. No source-to-bytecode hash, StateInit, real financial trace, tested escrow or refund implementation is provided. The repository's previously reported 20 baseline tests have not been rerun here. Source SHA-256 (raw file bytes as created in this worktree): `b0d38981b711d56298427606417cdb847119b55a1358367f1466b4839ecf841b`. This is not a code-cell hash.

The separate security-audit workflow requires target-controlled build/test execution in an OS-enforced sandbox with external network disabled, an empty allowlisted environment, read-only source and tools, scratch-only writes, and resource limits. No suitable sandbox was found on this host. Do not treat TVM Sandbox alone as that OS isolation. In an approved offline sandbox with the existing pinned dependencies, first run `node --test tests/settlement-runtime/f02-principal-ledger.test.js`, fix any harness/compiler issues, and then validate the actual custody implementation and authentic STON.fi behavior before publishing artifacts.

The [STON.fi LPAccount interface](https://docs.ston.fi/developer-section/dex/smart-contracts/v2/lpaccount) exposes asynchronous account observations and refunds; [TON Jetton guidance](https://docs.ton.org/applications/payments/jettons) requires authentication of the recipient wallet's notifications. Neither an LP notification nor an empty or stale account observation proves that every operation message has closed. [TON proof documentation](https://docs.ton.org/foundations/proofs/overview) is a potential research basis, not an implemented terminal proof.

Outstanding: an actual operation-isolated StateInit and escrow; Curve authorization and graduated economics; verified TON/Jetton custody and actions; gas and action-phase accounting; safe authenticated refunds and retries; LP wallet and Locker V3 integration; authenticated terminal evidence or a separately authorized trust model; deterministic compilation; complete Sandbox and regression suites; and independent security review. This experiment cannot be used for financial activation.
