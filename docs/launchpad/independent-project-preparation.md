## Implemented and reused

- Existing candidate/lifecycle builders now accept explicit metadata and pinned artifact injection. No defaults, financial contract source, bytecode, storage or message interfaces changed. Existing ANLTEST is never redeployed. New projects include their immutable draft UUID as the TEP-64 `anlgram_project_id` metadata entry; creator/metadata/project identity determine their new minter/Curve addresses. Standard precision/supply and Launchpad fixed 1B/9/80–20 economics remain distinct.
- `testnet-interface/projects/` adapts existing minter, Standard pinned code, migration-v2-plan, Locker V2 and vesting builders. `/api/projects/prepare` validates bounded same-origin Testnet input and produces only offline templates. There is no RPC, current fee quote, signing session, authorization, broadcast, ledger mutation or receipt claim in this endpoint. Exact StateInit, code/data hashes, payload hashes and operation-specific receipt expectations are exported. Existing receipt verification is not duplicated or substituted by JSON claims.
- Saved wizard distribution settings produce exact TEP-74 batches of 1–4 recipients, canonical duplicate rejection, distinct query/operation IDs, recipient previews and explicit unknown balances/fees. CSV imports validate before replacing previous recipients, limit size/extension and reset selection for repeat imports. Standard allocation budgets are checked with integer units. Launchpad cannot assign its reserved initial supply to free distributions or vesting.
- Existing vesting storage and transfer format encode the saved beneficiary, principal and UTC schedule. Months match the existing builder's 30-day convention. Prepared addresses and exact cliff/end times are disclosed; no deployment or escrow is claimed. Creator/recipient/beneficiary must be basechain: existing wallets enforce error333 on other workchains.
- Existing V2 binding/Locker builders derive separate destinations with 50–100%, 180/365 days/permanent, beneficiary/controller and migration operation ID. Default100% permanent stays intact. Pool/LP wallet destinations are expected values only; actual custody and unlock timestamps remain unknown. The legacy Curve/migrator is not silently rewired to V2.
- Existing Antigravity CSS and layout are reused unchanged. My Projects links only derived unverified addresses, keeps historical ANLTEST receipts clearly separate, retains drafts, and invalidates preparation/export after configuration edits. Exported JSON is not authority. Preparations remain in memory and are regenerated after reload; drafts are persistent. No local prepared state can reset or complete a financial operation.

Creation base0.20 TON and mandatory donation0.02 TON with the existing recipient are preserved. Standard creation templates attach0.20 TON plus the separate0.02 donation; the existing Launchpad component templates attach0.75 TON plus the separate donation. These attachments are not fee estimates, a maximum debit or proof of base-charge reconciliation. All real transactions still require fresh state, fees, ownership, exact owner approval and final receipt reconciliation. The recipient is absent from normal UI and present in the public-message export.

## Remaining blockers — not silently implemented or enabled

1. The V2 plan explicitly reports no executable compatible Curve/migrator handoff. Completing it requires review of a versioned interface/address migration; this release does not silently replace deployed interfaces or authorize financial DEX execution.
2. Foreign LP balance/issuance attribution and final withdrawal delivery require authentic contract capabilities/evidence. Existing lost-notification recovery proves a custody floor, not exact issuance or final beneficiary delivery. Independent STON.fi source/code and Router upgrade-trust review remain required. Router administration can upgrade and affect reserves; the accepted development trust model is unchanged.
3. Vesting downstream recipient failure/final delivery receipts and arbitrary per-user distribution reconciliation are not proven by dispatch or missing notifications. Their live execution remains disabled. No pending/failed/completed financial status is fabricated for unsubmitted templates. Multi-creator ownership, fresh fees and authentic final receipt acquisition must be wired to the existing protected operation ledger before public execution.
4. Original Curve #2 lock/fingerprint/history remain untouched; qualified independent review and authorized recovery are a separate blocked workstream. No signatures, broadcasts, nonce invalidations, minting, trades or TON expenditure occurred.
5. Mainnet is NOT READY. New-contract Testnet financial execution and end-to-end real buys/sells/refunds are still unverified. Sandbox success and an offline plan do not approve them.
